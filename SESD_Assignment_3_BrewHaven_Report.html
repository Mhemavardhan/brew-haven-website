1. Aim & Objectives

Aim: To design, develop, and version-control a responsive coffee shop website named Brew Haven equipped with an interactive online table reservation system, and deploy it live via GitHub Pages while demonstrating fundamental and intermediate Git operations including branching, merging, and merge conflict resolution.

Learning Objectives:

  • Apply essential Git version control commands: git init, git config, git status, git add, git commit, git log, git remote, git push, and git pull.
  • Construct modular feature branches (git branch, git checkout) and integrate them into the production branch (git merge).
  • Diagnose, inspect, and cleanly resolve a simulated three-way merge conflict (inspecting <<<<<<< HEAD, =======, and >>>>>>> conflict markers).
  • Configure and publish a static website globally using GitHub Pages.
  • Maintain industry-grade documentation, atomic commit logs, and responsive frontend design practices.

2. Scenario and Problem Statement

In modern software engineering, web applications require rigorous version control, collaborative branching strategies, and rapid static hosting deployment. In this project scenario, Brew Haven—an artisanal specialty coffee house—requires an interactive digital platform to showcase its handcrafted beverage menus, café ambience, location details, and allow patrons to reserve dining tables in advance.

The engineering challenge requires structuring a responsive frontend application using vanilla web standards (HTML5, CSS3, JavaScript ES6) without external heavy frameworks, managing iterative feature improvements via Git branches, safely resolving merge conflicts when team branches overlap, and configuring automatic cloud deployment on GitHub Pages.

The Brew Haven web platform is architected around five major user-facing modules:

  1. Header & Responsive Navigation Bar: Features sticky positioning, blur-filter backdrop, brand typography, and an animated mobile hamburger toggle drawer.

6.5 Step 5: Controlled Merge Conflict Generation & Resolution

To demonstrate intermediate version control mastery as shown in the reference assignment, a realistic scenario was constructed where two parallel branches updated the same hero title line in index.html.

  1. Branch 1 (feature/hero-headline-update): Set heading to "Artisanal Handcrafted Coffee Brewed Daily".
  2. Branch 2 (feature/hero-headline-design): Set heading to "Cozy Moments & Handcrafted Artisanal Coffee".
  3. Merging Branch 1 into main succeeded. Merging Branch 2 immediately triggered a three-way merge conflict.
$ git merge feature/hero-headline-design Auto-merging index.html CONFLICT (content): Merge conflict in index.html Automatic merge failed; fix conflicts and then commit the result. $ git status On branch main You have unmerged paths. (fix conflicts and run "git commit") (use "git merge --abort" to abort the merge) Unmerged paths: (use "git add <file>..." to mark resolution) both modified: index.html $ git diff diff --cc index.html index 27ad7a9,939c4fd..0000000 --- a/index.html +++ b/index.html @@@ -47,7 -47,7 +47,11 @@@ <div class="container hero-container"> <div class="hero-content"> <span class="hero-badge">Welcome to Brew Haven Café</span> ++<<<<<<< HEAD + <h1 class="hero-title" id="heroTitle">Artisanal Handcrafted Coffee Brewed Daily</h1> ++======= + <h1 class="hero-title" id="heroTitle">Cozy Moments & Handcrafted Artisanal Coffee</h1> ++>>>>>>> feature/hero-headline-design

Conflict Resolution Procedure: The conflict markers were removed, and the heading was harmonized to combine both product aspects: "Artisanal Handcrafted Coffee & Cozy Moments Brewed Daily". The resolution was staged and committed.

$ git add index.html $ git commit -m "Resolve merge conflict in hero section headline" [main f49fdad] Resolve merge conflict in hero section headline

8. GitHub Pages Deployment Procedure

  1. Open GitHub in your web browser and navigate to your repository: https://github.com/Mhemavardhan/brew-haven-website.
  2. Click on the Settings tab at the top right of the repository navigation bar.
  3. In the left sidebar under the Code and automation group, click on Pages.
  4. Under Build and deployment → Source, ensure "Deploy from a branch" is selected.
  5. Under Branch, select main from the branch dropdown, and leave the directory set to / (root).
  6. Click Save.
  7. Wait 60–90 seconds for GitHub Actions to complete the pages-build-deployment workflow.
  8. Refresh the page; a green banner will appear stating: "Your site is live at https://Mhemavardhan.github.io/brew-haven-website/".
  9. Click Visit site to confirm that the live website renders with all styling, images, menu filters, and table reservation functionality active.

10. Comprehensive Git Commands Quick Reference Table

Below is the complete reference table of Git commands as specified in the official SESD Assignment 3 curriculum:

S.No Command Name Syntax Purpose / Description
1 Initialize Repository git init Creates a new local Git repository in the current working directory.
2 Check Repository Status git status Displays the state of working directory and staging area (tracked, untracked, modified).
3 Configure Username git config --global user.name "Your Name" Sets the author username globally across all Git repositories on the system.
4 Configure Email git config --global user.email "email" Sets the author contact email globally for Git commit attribution.
5 Add Files to Staging Area git add filename / git add . Stages modified or untracked file(s) preparing them for the next commit.
6 Commit Changes git commit -m "Message" Records the staged snapshot permanently into the local repository history.
7 View Commit History git log / git log --oneline Displays a chronological log of all commits in the active branch.
8 Create Branch git branch branch_name Creates a new isolated pointer/branch for developing features independently.
9 Switch Branch git checkout branch_name / git switch Navigates between branches, updating the working directory to match the target branch.
10 Rename Branch git branch -m new_name Renames the current branch (e.g., git branch -M main).
11 Merge Branch git merge branch_name Integrates changes from the specified branch into the currently checked-out branch.
12 Add Remote Repository git remote add origin URL Links the local Git repository to a remote cloud repository (e.g., on GitHub).
13 Push to Remote git push -u origin main Uploads local commits to GitHub and binds upstream tracking with -u.
14 Push Updates git push Pushes subsequent committed changes to the tracked upstream remote branch.
15 Pull Latest from Remote git pull Fetches and merges commits from the remote repository into the local branch.
16 Clone Remote Repository git clone URL Downloads a complete copy of an existing remote repository onto the local machine.
17 Delete Branch git branch -d branch_name Safely deletes a local branch that has already been merged.
18 Show Changes git diff Compares unstaged working directory changes against the staging area or last commit.
19 Revert Last Commit git revert commit_id Creates a new inverse commit that safely rolls back specified historical changes.
20 Reset to Last Commit git reset --hard HEAD Discards all uncommitted changes in the working tree and staging area permanently.
